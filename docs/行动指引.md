# 千江月 · 行动指引

本文是这个网页应用的行事准则与推进路线。它回答三个问题：**这东西为什么值得做**、**一次「照见」该怎样发生**、**接下来按什么顺序做**。

---

## 一、一句话定位

> 输入你想表达的一句道理，看见它在古今中外被说过的样子，再用史案与你自己的处境把它压实成今天的动作。

不做的三件事：不做名言金句收藏夹（那只是列表），不做 AI 续写（那会稀释可信度），不做社交广场（那是另一个产品）。

## 二、为什么是现在这个做法

**问题**：人并不缺道理。人缺的是「这个道理真的被人验证过」的确信，以及「今天该做哪一步」的落点。大多数金句产品停在第一步——给你一句漂亮话，然后你关掉页面，什么都没变。

**赌注**：把四件事串成一条不可跳过的链路，用户走完就会有行动。这四件事是——

1. **同一性**：同一个道理，在不同文明里被独立说过。这证明它不是我编的。
2. **代价**：有人因为这个道理做成了，有人因为违背它垮掉了。这证明它不是鸡汤。
3. **照见**：三个问题把镜子转向我自己。这一步最容易被跳过，所以必须做成页面结构的一部分，而不是「你可以想想」。
4. **落点**：几条今天就能做的动作，可勾选、有进度。这是唯一能产生复利的部分。

**约束**：引文必须可查。宁可只收 15 条，也不放一句查不到出处的话——因为一旦用户发现一条编造的引文，整个产品的说服力归零，而且这个损失不可逆。

## 三、一次「照见」的用户旅程

| 步骤 | 用户心智 | 界面必须做的事 | 成功的信号 |
|---|---|---|---|
| 1 输入 | 「我有个想法，但说不清」 | 一个 96px 高的输入框，附 6 个示例；Enter 直接提交；输入太短/为空时抖动而非弹错 | 输入到提交 < 5 秒 |
| 2 映月 | 「原来这么多人都说过」 | 4–6 张引证卡，每张带地域年代 + 体裁 + 出处 + 一句按语；中国与域外各至少 1 条 | 至少扫读 3 张 |
| 3 照镜 | 「这件事原来这么严重」 | 一则史案，标明「正面 · 做成的人」或「反面 · 失衡的人」，末尾给「镜中所见」一句 | 停留 > 15 秒 |
| 4 起行 | 「我今天可以做一件」 | 3 条最小行动，勾选即保存，底部显示进度 | 至少勾选 1 条 |

**反例（明确不做）**：不要在首页放信息流；不要用无限下拉；不要在结果页插广告位；不要要求注册。

## 四、内容生产规范

一条主题必须同时齐备五要素，缺一不收：

```
id / name / gist        —— 主题名 + 一句话洞见（洞见必须是自己的话，不能是引文改写）
keywords ≥ 5            —— 用户可能怎么问它（含同义说法、俗语、错误说法）
canon ≥ 5，其中域外 ≥ 2  —— 引证：地域年代 / 体裁 / 原文 / 出处 / 按语
history                 —— 史案：正面或反面，必须有具体人名、时间、后果
questions ≥ 3           —— 只问处境，不问「你怎么看」这类空问题
actions ≥ 3             —— 今天能做完，不写「坚持」「努力」这类不可执行动作
```

**引文六条铁律**
1. **可查**：出处写到篇名或作品名。写不出来就不收。
2. **存疑标注**：拿不准的必须标 `存疑`，并在按语里说明它常见的误传路径。已有八例：黑格尔「学不到教训」、伏尔泰「誓死捍卫」、19 世纪「无人看见时的选择」、亚里士多德「吾爱吾师」、亚里士多德「卓越是一种习惯」、芝诺「两只耳朵一张嘴」、甘地「以眼还眼」、苏格拉底「我一无所知」。
3. **区分原话与转写**：如「以史为镜」原文是「以古为镜」；「优秀是一种习惯」是杜兰特对亚里士多德的概括。
4. **不跨主题重复**：同一句原文只出现一次，`tools/check-data.js` 会拦截。
5. **关键词不许用中性领域名词**：这类词不带方向，放哪个主题下都会把相反的意思吸过来。
6. **文学与电影要区分原句与译本**：外文附原文、写明中译与年份；电影台词标明片名年份，并注「台词非史料」。
第 5 条是有事故背书的。曾有用户输入「不要盲从经验」，系统把他送进了「前事不忘，后事之师」——
那是「要从前人经验里学」的道理，方向正好相反。根因就是「经验」这个中性词成了该主题的关键词。

**修法不是加否定词解析器。** 「不要盲从」里的「盲从」本身正是正确主题的关键词，任何按「否定词 + 宾语」
划范围的做法，都会把正确主题一起惩罚掉。真正的解法是三条：补齐缺失的主题（尽信书则不如无书）、
清掉方向不明的泛词（经验、习惯、说话、快、慢、强、曲、忍）、把这批用例固化成回归测试。

由此得出选词标准：**关键词要写这个主题自己的毛病词或德行词**——写「骄傲」不写「成功」，
写「急」不写「快」，写「盲从」不写「经验」。

提交前必须跑通：

```bash
node tools/stamp.js          # 改了资源就要重算指纹，否则浏览器拿旧 JS
node tools/check-data.js     # 2655 项检查，输出 ✓ 全部通过
```

**关于指纹**：GitHub Pages 对所有文件发 `Cache-Control: max-age=600`。不做处理时，
用户刷新可能拿到「新 HTML + 旧 JS」——刚修好的 bug 看起来像没修。stamp 按资源内容算指纹写进
`?v=`，自检第 5 节会校验它，忘了跑直接失败。页脚显示同一指纹，用户报问题时带上它，
就能立刻区分「缓存」与「代码」。这也是一次真实事故的产物：修好匹配后用户仍看到旧结果，
排查下来线上文件是对的、逻辑是对的，纯粹是 10 分钟强缓存。

## 五、现状（v0.1，已完成）

## 六、迭代路线

### v0.2 —— 让语料继续长（内容优先，不动架构）

| 事项 | 做法 | 验收 |
|---|---|---|
| 主题扩到 30 条 | 按用户真实提问补，优先补「关系」「金钱」「时间」「恐惧」四类 | 自检通过；每类至少 3 条 |
| 建立主题索引表 | 在 `docs/` 下维护一张「主题 × 关键词 × 已覆盖文明」矩阵 | 任一主题的域外引证 ≥ 2，且不集中于单一文明 |
| 引证溯源升级 | 有条件的条目补上具体篇章号（如《论语·子路》第几章） | 抽查 10 条，均可在线检索到 |

### v0.3 —— 让匹配更准（体验）

| 事项 | 做法 | 验收 |
|---|---|---|
| 同义词表外置 | 把散在 `keywords` 里的同义词抽成 `assets/synonyms.js`，多个主题共享 | 新增主题时不必重复写同义词 |
| 匹配结果可解释 | 详情页显示「因为你说到了『急』」，让用户知道为什么给这一条 | 用户能理解命中原因 |
| 未收录页可累积 | 把未命中的输入存本地，形成「待补主题」清单，一键导出 | 跑一周后能拿到真实长尾词 |

**不建议做的**：接入向量检索或大模型改写。匹配是确定性的、可测试的、零成本的，换成模型会让「同一输入得到不同结果」，反而破坏可信度。若将来要加，只能作为**未命中时的兜底建议**，并明确标注「非典籍原文」。

### v1.0 —— 让它真的改变行为（已完成）

| 事项 | 做法 | 状态 |
|---|---|---|
| 行动回访 | 勾选的行动在下次访问时询问「做到了吗」，只存在本地 | ✅ 首页横幅，记 `qjy.journal` / `qjy.outcome` |
| 主题串联 | 30 条道理串成一个语义环，每条与左右相邻两条相通 | ✅ `assets/related.js`，详情页「相通的另两条」 |
| 可打印的一页纸 | 触发打印，把四镜压进一张 A4 | ✅ 实测单页，余量约 55mm |
| 导出 Markdown | 一键下载当前主题全文 | ✅ 详情页「下载 Markdown」 |

**关于「主题串联」的设计取舍**：没有做「相似度推荐」，而是手工排了一个环。理由是相似度只能给出「像」，
给不出「接着说哪一条」——而学习路径需要的正是后者。这个环的读法本身是一种主张：

> 欲速 → 积累 → 专注 → 习惯 → 慎独 → 诚信 → 反求诸己 → 恕道 → 宽恕 → 制怒 → 慎言 → 防微
> → 环境 → 和而不同 → 留余地 → 柔 → 祸福 → 忧患 → 知足 → 满招损 → 自知 → 井蛙 → 尽信书
> → 学思 → 知行 → 启发 → 不耻下问 → 鉴往 → 惜时 → 生死 →（回到起点）

环的完整性由自检第 6 节守着：漏一条、重一条、指向不存在的主题，都会直接失败。

## 七、发布

**当前状态**：代码在私有仓库 `joffzxf/waili`，尚未开 Pages。

GitHub Pages 对**私有仓库**需要付费方案（Pro/Team 等）；公开仓库可免费启用。

**要上线，二选一：**

```bash
# A. 仓库转公开后启用 Pages（免费）
gh repo edit joffzxf/waili --visibility public --accept-visibility-change-consequences
gh api -X POST repos/joffzxf/waili/pages \
  -f "source[branch]=main" -f "source[path]=/"
# 站点地址：https://joffzxf.github.io/waili/

# B. 保持私有，改用其他静态托管（Cloudflare Pages / Vercel，均可连私有仓库）
```

**风险提示**：转公开意味着源码与全部语料公开，且该操作对外可见、不易回收。若不希望公开，选 B。

## 八、边界与风险

- **引文错误是最高风险**，且不可逆信誉损失。任何新增内容必须先过自检脚本，且人工复核出处。
- **不要收录有争议的现代语录**（名人名言的真伪是重灾区）。已有四条存疑条目作为正面示范：标注比删掉更好。
- **不做用户生成内容**。一旦允许投稿，引文质量就无法保证，产品的地基会塌。
- **隐私**：无后端、无第三方请求；唯一本地存储是勾选进度与明暗偏好，可随时清除浏览器数据删除。

## 九、怎么算这件事成了

不看访问量，看三个数：

1. **进入第肆节的比例** ≥ 60%（说明前三节没有把人赶走）
2. **至少勾选一条行动的比例** ≥ 30%（说明道理真的落地了）
3. **二次访问率** ≥ 15%（说明它被当成工具，而不是一次性的好奇）

这三个数都不需要后端——本地埋点即可，甚至可以先靠手工抽样。
