# 千江月 · 一句道理，千江映月

> 你想表达什么道理？总有人替你说过，而且说得比你好。

输入一句你想表达的道理——可以是一句断言、一个成语、一句俗语，甚至只是「不要急功近利」这样的大白话——
它会找出古今中外在说同一件事的典籍、语录、成语、寓言与史诗，再用**以史为镜**的史案照见它，
最后落成几条你能勾选的**最小行动**。

同一个道理，孔子说过，老子说过，伊索说过，希腊的悲剧作家也说过。
它们不是重复，是**千江映月**：一千条江，映的是同一轮月。

---

## 它做什么

一次「照见」会给你四镜：

| 分节 | 内容 | 作用 |
|---|---|---|
| **壹 · 同此一念** | 5–6 条跨文化引证，标注原文、出处、地域年代与体裁 | 让你看见这个道理被不同语言说过的样子 |
| **贰 · 以史为镜** | 一则史案，分「正面 · 做成的人」与「反面 · 失衡的人」 | 让道理从抽象变成代价 |
| **叁 · 照见自己** | 三个追问 | 把镜子转向读者 |
| **肆 · 起而行之** | 3–4 条最小行动，可勾选、自动记忆进度 | 道理不落地，就只是漂亮话 |

此外还支持：

- **文与影** —— 小说、戏剧、电影的条目单独成区，**以那句台词/文本为主角**排成海报：
  8 种版式（居中、竖排、上下分栏、角落、斜置、窄栏、索引、截句）按主题与序号轮换；
  美术是程序生成的几何与配色，同一部作品永远同一张 **（不用剧照——剧照有版权）**；
  译文一律附外文原文
- **相通的另两条** —— 40 条道理被串成一个语义环，每条与左右相邻的两条相通，从一条走到下一条，而不是看完就断
- **行动回访** —— 勾过的行动会记账，下次打开时会问你一句「做到了吗」，答完记在本机
- **一页纸** —— 「打印一页」把四镜压进一张 A4（实测单页，余量约 55mm）
- **三观坐标** —— 12 句可被反对的话，四根轴（事在人为↔顺势、个体↔关系、守原则↔看后果、入世↔出世）。
  结果给出轴分、与你最亲近的文明、最认同与最反对各一条，可生成坐标图并复制分享链接。
  **明写不是心理测量**，不给类型标签当身份，不排名
- **卡片级动作** —— 每条引证右下角就有「收藏／复制」，海报下有「存图 3:4 / 方图 1:1 / 壁纸 9:16」。
  动作贴在动机旁边，不堆到页尾
- **我的册子** —— 收藏的条目按主题聚合，可切换两套预置分类法（按场景／按学科），
  可导出／导入 JSON，换设备不丢
- **导出 Markdown** —— 「下载 Markdown」把整条道理存成本地文件

以及按主题浏览、随机取一理、一键复制全文、复制分享链接（带 `#/t/<id>` 深链）、明暗主题。
勾选进度、回访记录与偏好全部存在浏览器本地（`localStorage`），不上传任何数据，也没有后端。

## 怎么跑

**无需安装、无需构建、无外部依赖。**

- 直接双击 `index.html` 即可在浏览器打开；或
- 起一个本地服务器（推荐，剪贴板 API 在 `file://` 下受限）：

```bash
node tools/serve.js 8347     # 打开 http://127.0.0.1:8347/
```

## 自检

语料与匹配逻辑都有自动化检查，共 **5998 项**：

```bash
node tools/check-data.js
```

它会检查：每条引证的 `地域/体裁/原文/出处/按语` 五要素是否齐全、出处格式是否可追溯、
主题 id 是否唯一、同一句原文是否被重复填充到多个主题、正面范例与反面教训是否都存在，
一份 82 条的真实提问用例（「不要急功近利」「说到做不到怎么办」……）是否都命中预期主题，
一组**反向语义**用例是否不会被听反，以及无关输入（「今天天气怎么样」）不会被硬凑成某个主题。

反向语义那组是有来历的：曾有用户输入「不要盲从经验」，系统把他送进了「前事不忘，后事之师」——
那是「要从前人经验里学」的道理，方向正好相反。根因是「经验」这类**中性领域名词**被当成了关键词，
它能朝任意方向吸附。修法不是加个否定词解析器（「不要盲从」里的「盲从」本身就是正确主题的关键词，
否定解析会在这一步就崩掉），而是：补上缺失的主题、清掉方向不明的泛词、把这批用例固化成回归测试。

> **改了语料或代码之后，务必跑一次 `node tools/stamp.js`。**
> GitHub Pages 一律发 `Cache-Control: max-age=600`，浏览器可能拿「新 HTML + 旧 JS」，
> 表现就是「明明改了却没生效」。stamp 会按资源内容算指纹写进 `?v=`，自检第 5 节会校验它；
> 忘了跑，自检直接失败。

输出 `✓ 全部通过` 才会提交。这不是形式主义——引文一旦编错，整个产品的价值就是负的。

## 内容规范（重要）

这个仓库把**引文的可靠性**当作第一约束：

1. **不编造引文。** 每条引证都注明可查的出处（篇名或作品名）。
2. **存疑就标注。** 例如「品格是你在无人看见时所做的选择」标为 `存疑`，并说明「常被归于 19 世纪英美作家，出处存疑」；
   「人类从历史中学到的唯一教训……」标为常误归黑格尔、实际出处存疑。
3. **区分原话与转写。** 「以史为镜」通行说法，原文实为「以古为镜」，条目里写明了这一点；
   「优秀是一种习惯」是杜兰特对亚里士多德的概括，不是亚里士多德原话，条目里也写明了。
4. **同一句原文不跨主题重复**，自检脚本会拦。
5. **关键词不能是中性领域名词。** 「经验」「习惯」「说话」这类词本身不带方向，放在哪个主题下都会把相反的意思吸过来。
   关键词要写这个主题自己的**毛病词**或**德行词**（写「骄傲」不写「成功」，写「急」不写「快」），
   并且要有反向语义用例守着。
6. **文学与电影的条目，必须区分「原句」与「译本」。** 外文作品一律附原文，并写明中译出自谁、哪一年；
   电影台词要标明片名与年份，并在按语里注明「这是台词，不是史料」。
   理由：译文的措辞随译者而变（《基督山伯爵》法文说的是「两个词」，中译常作「五个字」），
   电影台词更是常被当成真实名言（甘地那句「以眼还眼」至今查无实据）。这两类引证的讹传率比典籍高得多。
7. **论文类引证要写到作者、篇名、期刊、卷期**，能被人顺手查到；**有复现争议的必须把争议写出来**。
   典型例子是「成长型思维」：2018 年对 386 项研究的元分析把效应量打到约 0.1，这条校正本身就作为一条引证收在同一主题里。
   标注争议不是拆自己的台——它是这个产品唯一拿得出手的东西。
8. **译文必须附原文，且只能附原语种的原文。** 三档：`o` 原语种原文、`oEn` 英译见证（原语种未能核实到权威出处时使用，
   页面标「英译」，绝不冒充原文）、`noOrig` 显式声明无单一原句。
   **找不到权威出处的外文原文就不写**——宁可空着，不可编一条看起来像原文的东西。
   英文原作（梭罗、爱默生、弗罗斯特、达尔文、波普尔等）的原文就是英文，记在 `o`，不标「英译」。
   自检为硬约束：缺一条即构建失败。当前 114 条境外引证：原文 38、英译见证 25、显式无原句 29、原句内嵌 22。

宁可少收一条，也不放一句查不到出处的话。

## 技术说明

- 纯前端静态站点：原生 JS（ES5 语法，无框架、无打包、无 `node_modules`）。
- 匹配算法：中文统一归一化 → 关键词精确命中（权重最高）→ 二元字组重合度（≥60% 视为近似）
  → 主题名与洞见句的近似度加权。命中阈值以上才给结果；否则走「未收录」页。
  未收录页里只有真的算出分来才标「可能相近」，全部 0 分时改称「不妨从这几条看起」——
  不给巧合排序披上「相关」的外衣。
- 无网络请求、无第三方脚本、无 Cookie。唯一写入的是 `localStorage` 里的勾选进度与明暗偏好。
- 缓存策略：资源 URL 带内容指纹（`?v=<sha256 前 10 位>`，由 `tools/stamp.js` 生成），
  页脚也显示同一指纹。这样「改了却看不到」一眼就能分辨是缓存还是代码问题——报问题时带上页脚那串号即可。
